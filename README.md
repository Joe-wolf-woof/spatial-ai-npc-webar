# Spatial AI NPC

物理空間を認識して自律行動する WebAR エージェント。

スマホのカメラ越しに3Dアバター（AIエージェント）が出現し、マルチモーダルAIが現実空間の物体や状況を認識して、文脈に応じた雑談・作業サポートを音声対話とモーションで返す、アプリ不要のWebAR体験を目指すポートフォリオ作品。

## 現在の状態：Phase 3（ハイブリッド化＋実モデル対応）

- three.js で3Dアバター（プレースホルダー）をブラウザに表示し、地面の影で接地感を表現
- 「話しかける」ボタン → AIが `{ text, emotion }` のJSONで返答 → Web Speech API で読み上げ、感情タグに応じてアバターが動く
- 「カメラを開始」→ カメラ映像がステージ背景になり、アバターが重なる
- 「いまの様子を見て話す」→ 現在のフレーム（長辺768pxに縮小したJPEG）を Gemini に送り、空間の状況に応じた声かけを返す。10秒ごとの自動観察も可能
- ローカル検知（COCO-SSD）がカメラ映像を1.5秒間隔で推論し、物体名・信頼度・推論msを即表示。新しい物体が現れたときだけ Gemini へ自動で問い合わせる（仮説Aのハイブリッド構成）
- 柔軟検知（OWL-ViT）をONにすると、自由ラベルのプリセット（観葉植物／吊り下げ植物／洗濯物／コーヒーカップ／本／ノートPC／人／椅子／ベッド／猫／犬）で15秒間隔＋手動実行で中間層の検出も走る。3層の推論msを並べて表示する
- 実モデル対応（Phase 3-B）：`assets/models/avatar.glb` があれば自動で読み込み、スケール・位置を正規化して差し替える。アニメーションクリップがあれば感情タグで切り替え、無ければモデル全体のプロシージャルモーション＋名前付きパーツ（Head / Tail）の動きで表現する。同梱の avatar.glb はコード生成したローポリ風オオカミ（暫定モデル）
- 接地（Phase 3-C）：ステージ（カメラ映像）をタップすると、Raycastで地面平面上の位置を求め、アバターがその位置へ歩いて移動する。移動中は進行方向を向き、脚パーツのあるモデルは脚を振って歩く。着くと正面へ向き直す。タップ位置にはリングマーカーを表示し、地面と交わらない上方向のタップでも奥側に配置して反応する。GLBの読み込み時は頭の位置から向きを自動補正し、モデルが正面（+Z）を向くようそろえる
- ローカル検知msとGemini応答msを並べて表示。ベースライン実測は 11,442 ms（Phase 2・スマホ実機）
- Gemini API キーを設定すれば実API応答、未設定ならモック応答で動作確認可能（視覚連動のモックは固定文）
- モデルは3.x系から自動フォールバック（新規キーでは2.x系が404になるため）

## 仮説と検証（本作品の設計判断）

### 仮説A：レスポンス遅延の克服
- 問い：カメラ画像を毎回LLMに送ると応答が5秒以上かかり、体験が損なわれるのではないか。
- 計測（Phase 2・スマホ実機）：毎回 Gemini へ画像を送る方式の応答は **11,442 ms**（2026-11-10 実測）。仮説は裏付けられた。
- 対応方針（Phase 3で実装）：3層カスケード構成。
  - 第1層：ローカルの軽量物体検知（TensorFlow.js / COCO-SSD、lite_mobilenet_v2）を1.5秒間隔で回し、物体名と推論msを即表示（スマホ実機で 143ms を実測）。
  - 第2層：オープンボキャブラリ検出（OWL-ViT / Transformers.js）。COCOの固定クラスで拾えない対象（吊り下げ植物・洗濯物など）を自由ラベルで検出する中間層。数秒間隔で実行。
  - 第3層：Gemini。画像を送るのは「新しい物体が現れたとき（20秒クールダウン付き）」と「ユーザーが明示的に聞いたとき」だけに絞り、深い文脈理解と会話を担当。
- 画面下部に「COCO-SSD ms ／ OWL-ViT ms ／ Gemini ms」を常時並べて表示し、各層の遅延を比較できるようにした。
- 実測で得た制約（2026-11-10）：OWL-ViT は WASM では 18,415ms と実用外だったが、WebGPU（fp16）では 5,042ms まで短縮。ただし常時推論は端末の発熱（サーマルスロットリングでテザリング制限に至った）ため、熱対策として「推論msの悪化を検知して検知間隔を自動で広げる適応間隔」「柔軟検知は15秒間隔＋手動実行ボタン」「画面が隠れている間は推論停止」を入れた。遅延だけでなく熱も設計制約として扱う。

### 仮説B：空間UIとアバターの立ち位置
- 問い：アバターが映像の中で浮いて見えると没入感が削がれるのではないか。
- 対応方針：平面検知（Raycast）で床・机上に影とともに設置する。Phase 1では固定地面＋ShadowMaterialで最小実装済み。
- 実装（Phase 3-C）：タップ位置からRaycastで地面平面（y=0）との交点を求めてアバターを移動させる配置を実装した。影は地面が受け、遠くへ置くほど遠近で小さく見えるため、映像内での「置かれている感」は再現できている。一方で、これは固定カメラ＋仮想地面での近似であり、実空間の平面検知（WebXRのヒットテスト等）そのものではない。その差分は今後の課題として明記する。

## ロードマップ

- Phase 1（済）：最小構成 — 3D表示＋ボタンでAI応答を読み上げ
- Phase 2（済）：視覚情報の連動 — カメラフレームを Gemini へ送り、空間の状況に応じた声かけを返す（手動＋10秒間隔の自動観察、応答時間の表示）
- Phase 3（済）：ハイブリッド化 — ローカル物体検知（COCO-SSD）との統合と遅延の比較表示（仮説Aの実装・検証）。実モデル対応（GLB読込・正規化・モーション切替、暫定モデルはコード生成オオカミ）と、接地（タップ配置・Raycast）も実装した
- Phase 4：構造化・発信 — 技術記事、リポジトリ整理、1分デモ動画

## 起動方法

ES Modules を使うため、ローカルサーバー経由で開く（ファイルを直接開くと動きません）。

```powershell
# 例：Python が入っている場合（このフォルダで実行）
python -m http.server 8000
# → ブラウザで http://localhost:8000 を開く
```

VS Code の Live Server 拡張でも可。スマホで試す場合は HTTPS 環境（または同一LAN＋適切な設定）が必要（カメラ利用は Phase 2 以降）。

## メモ

- Gemini API キーは画面の「設定」から入力し、ブラウザの localStorage にのみ保存されます。コードやリポジトリにキーを直書きしないこと。
- 実モデルを使う場合は GLTF/GLB 形式で `assets/models/avatar.glb` に配置してください（同梱の暫定オオカミと差し替えるだけです）。スケールと位置は自動で正規化されます。
